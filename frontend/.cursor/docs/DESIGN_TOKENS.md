# Design Tokens

Last verified against `src/app.css` on 2026-10-04.

> This page replaces an older version that documented token names the site never shipped
> (`--spacing-4`, `--font-size-lg`, `--transition-base`, `--z-*`, `--breakpoint-*`, and a list
> of "missing" accent and status tokens that have since been added). For the current rules read
> `.interface-design/system.md`; for values read `src/app.css`. This page is an orientation,
> not a copy of either.

## Where tokens live

| File                                 | Role                                                                                                                                                                                   |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/app.css`                        | The only place tokens are defined. Light values on `:root`, dark overrides on `.dark`, font stacks in `@theme`                                                                         |
| `src/lib/constants/design-tokens.ts` | Index of the tokens for the `/design-system` previews. `design-tokens.test.ts` parses `app.css` and fails on drift; any token whose prefix is in `COVERED_PREFIXES` must be registered |
| `static/tokens.css`                  | Generated by `pnpm tokens` (runs on `prebuild`) for consumers outside this app. `tokens-css.test.ts` fails if the committed file is stale                                              |

## Families

| Family                    | Tokens                                                                                                                                          | Rule                                                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Colour roles              | `--bg-primary`, `--bg-secondary`, `--text-primary`, `--text-secondary`, `--text-muted`, `--border-color`                                        | Roles, not hues. `.dark` swaps values only                                                                                       |
| Inverse surface           | `--bg-inverse`, `--surface-on-inverse`, `--border-on-inverse`, `--text-on-inverse`, `--text-on-inverse-muted`, `--accent-on-inverse`            | The always-dark footer. Does not flip with the theme                                                                             |
| Accent                    | `--accent-primary`, `-hover`, `-light`, `-dark`, `-text`, `-10/-20/-30`, `--accent-gradient-start/end`                                          | Use `--accent-primary-text` for accent text (theme-flipped for AA). `--accent-primary-light` is for fills, dots and borders only |
| Category accents          | `--accent-professional`, `--accent-independent`, `--accent-experiment`, `--accent-infra` (plus tints)                                           | A kind of work, not a state. `--accent-infra` is the `/infra` dashboard accent                                                   |
| Status                    | `--status-{success,warning,error,info}`, `-text`, `-10/-20`                                                                                     | Bare token is the fill; `-text` is the readable end and flips per theme                                                          |
| Data viz                  | `--viz-series-1…5`, `--viz-series-1…8-dense`, `--viz-grid`, `--viz-axis`, `--viz-reference`, `--viz-structure`, `--viz-quiet`, `--viz-conflict` | Choose the ramp by mark count; chart chrome is never a series                                                                    |
| Surfaces                  | `--surface-raised`, `--scrim-subtle`, `--scrim-soft`, `--border-subtle`, `--border-soft`, `--ink-faint`, `--ink-dim`, `--ink-quiet`             | Ink-on-surface alphas that invert under `.dark`                                                                                  |
| Font                      | `--font-sans` (Geist Sans), `--font-serif` (Source Serif 4), `--font-mono` (Geist Mono)                                                         | Sans for interface and headings; serif for note and case-study reading prose only; mono for measured values and identifiers      |
| Type size                 | `--type-2xs` (0.625rem) … `--type-4xl` (4.5rem): `2xs, xs, sm, base, md, lg, xl, 2xl, 3xl, 4xl`                                                 | Step names. Reading text is `--type-md`                                                                                          |
| Leading, tracking, weight | `--leading-{tight,snug,normal,relaxed}`, `--tracking-{tight,normal,wide,wider,widest}`, `--weight-{light,regular,medium,semibold,bold}`         | Separate scales; they do not pair one to one with sizes                                                                          |
| Spacing                   | `--space-2xs` (0.25rem) … `--space-5xl` (8rem): `2xs, xs, sm, md, lg, xl, 2xl, 3xl, 4xl, 5xl`                                                   | Step names, never numeric: the scale is non-linear                                                                               |
| Rhythm                    | `--section-y`, `--section-y-lg`, `--section-y-mobile`, `--section-x`                                                                            | `-lg` only for sections that deliberately breathe more                                                                           |
| Layout                    | `--content-max` (72rem), `--measure-prose` (65ch)                                                                                               | One section width, one reading measure (see system.md, Layout)                                                                   |
| Radius                    | `--radius-{xs,sm,md,lg,xl,full}`                                                                                                                |                                                                                                                                  |
| Elevation                 | `--shadow-{sm,md,lg}`                                                                                                                           | Redefined under `.dark`                                                                                                          |
| Motion                    | `--duration-{fast,base,slow}`, `--ease-out`, `--ease-in-out`                                                                                    | Gate decorative motion on `prefers-reduced-motion: no-preference`                                                                |

Values are deliberately not repeated here. Read them in `app.css`, or browse
`/design-system/color`, `/design-system/type`, `/design-system/spacing` and the other
foundation cards in `pnpm dev`.

## Using tokens

```svelte
<style>
  .card {
    padding: var(--space-lg);
    border: 1px solid var(--border-color);
    border-radius: var(--radius-lg);
    background: var(--surface-raised);
    color: var(--text-secondary);
    transition: background-color var(--duration-base) var(--ease-out);
  }

  .card-figure {
    font-family: var(--font-mono);
    font-size: var(--type-sm);
    color: var(--text-primary);
  }
</style>
```

- Tailwind utilities are fine for layout (`flex`, `grid`, `gap-*`). Colours come from tokens,
  not Tailwind palette classes such as `bg-white` or `text-gray-900`.
- Dark mode needs no per-component overrides when the component uses tokens. Reach for
  `:global(.dark) .x { ... }` only when a token genuinely cannot express the difference.

## Adding a token

1. Add it to `src/app.css` (`:root`, and `.dark` if the value flips).
2. If its prefix is covered (see `COVERED_PREFIXES` in `design-tokens.ts`), register it in the
   matching group in `design-tokens.ts` with a usage note. `design-tokens.test.ts` fails until
   you do.
3. Run `pnpm tokens` so `static/tokens.css` matches, or `tokens-css.test.ts` fails.
4. A new token family also needs a line in `frontend/.design-sync/conventions.md`, the header
   of the Claude Design bundle; `design-system-styles.test.ts` fails on a family it never
   documents.
